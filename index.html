The 4 Core Stages of Git

Git is not just a backup tool—it is a transition state machine. Files travel across four distinct environments. Click any stage to inspect its file state and active transitions.

01. LOCAL FS

Working Directory

Your real files on disk. Any edit, creation, or deletion starts here before Git tracks it.

Unmodified | Modified | Untracked Inspect: git status / git diff
02. CACHE

Staging Area (Index)

The staging room for your next snapshot. Lets you craft precise, atomic commits piece-by-piece.

Staged for next commit Inspect: git diff --staged
03. LOCAL REPO

Local Repository

Permanent commit snapshots inside your .git/ directory. Where HEAD points.

Committed history (HEAD) Inspect: git log --oneline
04. CLOUD / SERVER

Remote Repository

Central server hosted on GitHub, GitLab, or Bitbucket for asynchronous team collaboration.

origin/main, origin/dev Inspect: git remote -v
Moving Forward ➔
git add <file> (Work ➔ Stage) git commit -m "..." (Stage ➔ Local) git push origin <branch> (Local ➔ Remote)
Pulling Back ⬅
git fetch / git pull (Remote ➔ Local) git restore --staged <file> (Stage ➔ Work) git restore <file> (Discard edits in Work) git reset --soft HEAD~1 (Local ➔ Stage)

🚨 Emergency Room

Git Rescue 911: "Oh Crap, Git!"

We've all been there: accidentally committed to the wrong branch, leaked a token, wiped a branch, or ended up in a detached HEAD. Here are the exact battle-tested remedies.

🆘
PANIC "I committed to the wrong branch (e.g. directly on main)!"
▼

You wanted to create a new feature branch, but accidentally made commits straight onto main without switching first. You need to migrate those commits to a new branch and restore main.

git branch feature-login && git reset --hard HEAD~1 && git checkout feature-login

How it works: Creates feature-login pointing at your current commit, rewinds main by 1 commit safely, then switches to your new branch. No work lost!

SECURITY "I accidentally committed sensitive credentials (.env or API key)!"
▼

If you haven't pushed yet, undo the commit while keeping all changes in your working directory, remove the file from Git tracking, and add it to .gitignore.

git reset --soft HEAD~1 && git restore --staged .env && echo ".env" >> .gitignore

Notice: If already pushed to a public remote, revoke/rotate the secret immediately! A Git history rewrite tool like git-filter-repo or BFG is required to scrub old pushed blobs.

TYPO / FORGOT "I made a commit with a typo in the message or forgot to include a file"
▼

Amend allows updating the most recent commit without creating a messy "fix typo" commit in your log.

git add forgotten-file.js && git commit --amend -m "feat: corrected commit message"

Tip: If you only want to add the file without changing the message, use: git commit --amend --no-edit.

CATASTROPHE "I ran 'git reset --hard' and deleted my recent work! Is it gone forever?"
▼

In Git, almost nothing that was ever committed is truly lost! git reflog keeps a secret log of every time HEAD moved in the last 30 to 90 days.

git reflog && git reset --hard HEAD@{1}

Rescue step: Run git reflog, find the SHA hash from right before you executed the fatal command, and run git checkout -b rescue-branch <SHA>.

ACCIDENT "I accidentally deleted a branch with 'git branch -D'!"
▼

A branch in Git is merely a 41-byte text file containing a commit SHA. When you delete a branch, only the pointer is removed; the commits still exist in your object database!

git reflog | grep "checkout: moving" && git checkout -b <branch-name> <SHA>
CONFLICT "I am in the middle of a bad merge conflict or rebase loop and want to ABORT!"
▼

Take a breath! You can cleanly abort and return your repository to the exact pristine state it was in before starting the merge or rebase.

git merge --abort # If merging | git rebase --abort # If rebasing
HEAD "Git says 'You are in detached HEAD state'. What does that mean?"
▼

Normally HEAD points to a branch name (which points to a commit). A detached HEAD means HEAD is pointing directly to a specific commit. If you commit here, no branch tracks it.

git switch -c new-experimental-branch # Keep work | git switch main # Discard and go back
SHARED REMOTE "I pushed a bad commit to production main! How do I safely undo it?"
▼

Never use git reset on public branches because it rewires shared history and breaks teammates' repositories. Instead, use git revert to record an inverse commit.

git revert <bad-commit-hash> && git push origin main
Deep Understanding

Under the Hood: How Git Actually Works

Underneath the CLI commands, Git is not an incremental diff storage engine. Git is a content-addressable key-value store powered by a Merkle Directed Acyclic Graph (DAG).

🗂 The .git Anatomy

Every Git repo has a .git hidden directory that holds 100% of the project history, configuration, and state:

  • HEAD: Points to current active ref (e.g. ref: refs/heads/main)
  • objects/: Zlib-compressed content-addressed blobs & trees
  • refs/heads/: Branch tip pointers containing 40-character SHAs
  • index: Binary file caching the staging area snapshot
  • config: Local repo configuration, remotes, and aliases

🔀 Merge vs Rebase

Understanding when to merge and when to rebase keeps Git history clean and comprehensible:

Merge: preserves exact history & branch timeline. Creates a 2-parent merge commit.
Rebase: replays commits on top of base. Produces a pristine linear history.

Golden Rule of Rebase: Never rebase commits that you have already pushed to a shared remote repository!

🏷 Conventional Commits

Standardize commit messages so machines and humans can generate automated changelogs and semantic versions:

feat: New user-facing capability
fix: Bug fix in production
refactor: Code restructure, no API change
perf: Performance improvement
chore: Build scripts, dependencies, setup

The 4 Fundamental Git Object Types

1. Blob
Stores raw binary file contents compressed with zlib. Does NOT store filename, timestamp, or permissions!
2. Tree
Represents a directory. Contains a list of filenames, execution modes, and SHA-1 pointers to blobs or sub-trees.
3. Commit
Points to a top-level Tree object, parent commit(s), author timestamp, committer info, and commit message.
4. Annotated Tag
Permanent reference pointing to a specific commit object with a tagger identity, date, GPG signature, and message.

Supercharge Your ~/.gitconfig

Professional Git users save dozens of keystrokes every hour with curated aliases and global default settings. Paste this snippet directly into your ~/.gitconfig file.

  • ✔ git lg: Visual ASCII branch graph tree with author & relative time
  • ✔ git st: Short status showing untracked and branch tracking delta
  • ✔ git undo: Instantly undo last commit while preserving code in staging
  • ✔ git discard: Restore modified files to clean workspace
  • ✔ git aliases: Display list of your configured custom shortcuts
[alias]
  # Visual graph log
  lg = log --graph --pretty=format:'%Cred%h%Creset -%C(yellow)%d%Creset %s %Cgreen(%cr) %C(bold blue)<%an>%Creset' --abbrev-commit --date=relative
  
  # Status & shortcuts
  st = status -sb
  co = checkout
  br = branch
  ci = commit
  
  # Safe undo & stage
  unstage = restore --staged
  discard = restore
  undo = reset --soft HEAD~1
  amend = commit --amend --no-edit

  # Show all aliases
  aliases = config --get-regexp alias

[init]
  defaultBranch = main

[pull]
  rebase = true

[push]
  autoSetupRemote = true
